# Juliet: первое измерение эффекта Module 0 с полной разметкой

Дата: 2026-08-26
Датасет: [Juliet C/C++ 1.3](https://samate.nist.gov/SARD/test-suites/112) (SARD,
NIST), 64 099 тест-кейсов, 118 CWE
Подкорпус: **все межфайловые варианты `_51a`/`_51b`** — 1767 файлов, 44 CWE
Детектор: baseline `static`, обученный на Devign, порог 0.5

---

## 1. Почему именно этот датасет

Разметка **полная по построению**: в Juliet каждая функция помечена именем —
`bad` означает уязвимую, `good` безопасную. Это не список известных CVE, а
метка на каждой из 5127 функций, поэтому precision и recall считаются честно.

Варианты серии `51` устроены ровно под нашу задачу: поток данных разнесён по
двум файлам.

**Файл A** (`_51a.c`):
```c
void CWE121_..._51_bad() {
    char * dataBadBuffer = (char *)ALLOCA((10)*sizeof(char));
    data = dataBadBuffer;
    CWE121_..._51b_badSink(data);      /* вызов в другой файл */
}
```

**Файл B** (`_51b.c`):
```c
void CWE121_..._51b_badSink(char * data) {
    char source[10+1] = SRC_STRING;
    memcpy(data, source, (strlen(source) + 1) * sizeof(char));   /* off-by-one */
}
```

Ни одна функция по отдельности не уязвима: первая просто отдаёт указатель,
вторая копирует в буфер, длины которого не знает. Уязвимость существует только
в связке.

После `--inline-depth 2` Module 0 подставляет тело `badSink`, и `ALLOCA(10)`
оказывается в одном тексте с `memcpy(..., strlen(source)+1)` из `char[10+1]`.
Локальная переменная `data` переименована в `data_i1` из-за коллизии с
одноимённой у вызывающего.

## 2. Module 0 на Juliet против libtiff

| | libtiff 4.0.9 | **Juliet `_51`** |
|---|---|---|
| юнитов с инлайном | 15.2 % | **93.5 %** |
| усечено бюджетом | 31.0 % | **0 %** |
| рост размера | ×1.17 | ×2.31 |
| разрешено вызовов | 43 % | 59 % |

Нулевое усечение принципиально: на libtiff треть юнитов теряла часть контекста,
здесь ни один. Значит измеряется именно эффект инлайнинга, а не его
взаимодействие с потолком окна.

## 3. Два обязательных предупреждения об интерпретации

### Метка утекает через имя функции

В Juliet имя содержит `bad` или `good` — то есть **метка выводится из имени в
100 % случаев**. Тривиальный классификатор по подстроке имени даёт AUC 1.0.
Абсолютные метрики на этом датасете заражены и сами по себе бессмысленны.

Наш детектор обучен на Devign и этой подсказки не знает, но полагаться на это
нельзя.

**Что остаётся валидным:** сравнение `depth=0` против `depth=2`. Функции те же,
имена те же, различается **только подставленный код**. Поэтому Δ метрик
атрибутируется инлайнингу, а абсолютные значения — нет.

### Детектор не переносится на Juliet

Devign — реальный код FFmpeg/QEMU; Juliet синтетический, шаблонный, с огромным
объёмом одинакового обвеса. Абсолютные цифры это отражают.

## 4. Результат: суммарно

5127 размеченных функций (уязвимых 1772, безопасных 3355).

| | acc | precision | recall | F1 | **AUC** |
|---|---|---|---|---|---|
| depth = 0 | 0.459 | 0.156 | 0.128 | 0.141 | **0.326** |
| depth = 2 | 0.637 | 0.212 | 0.019 | 0.034 | **0.448** |

Рост accuracy обманчив: при depth = 2 модель флагует втрое реже (7.6 % против
29 %), а поскольку 65 % выборки безопасны, «молчать чаще» механически поднимает
accuracy и обрушивает recall до 0.019. Смотреть надо на AUC.

AUC 0.326 при depth = 0 — **хуже случайного угадывания**: модель систематически
ставит уязвимым функциям более низкий скор, чем безопасным.

## 5. Результат: по типам функций — главное

Разделение по роли в потоке данных.

| Группа | n | уязв. | AUC d0 | AUC d2 | **Δ** | инлайн |
|---|---|---|---|---|---|---|
| **caller** (передаёт данные) | 2996 | 883 | 0.286 | **0.545** | **+0.260** | 90 % |
| **sink** (принимает данные) | 2131 | 889 | 0.390 | 0.366 | −0.024 | 74 % |

**Инлайнинг помогает ровно там, где предсказывает теория, и не помогает там,
где по устройству не может.**

### Caller: +0.260 AUC

Для вызывающей функции недостающая информация — что именно делает callee — при
инлайне подставляется. AUC переходит из области хуже случайного (0.286) в
область лучше случайного (0.545).

Это первое количественное подтверждение, что Module 0 делает то, ради чего
построен.

### Sink: −0.024, и это принципиально

Sink-функция — лист. Она вызывает только `memcpy`, `strcpy`, `printLine`, то
есть функции из списка `never_inline`, которые мы намеренно не подставляем
(решение D-004: это признаки, на которых обучена модель). У 553 из 2131
sink-функций (26 %) не оказалось ни одного пригодного для инлайна вызова.

Недостающая информация — **размер полученного буфера** — находится не в callee,
а у **вызывающего**. Инлайнинг callee в caller эту информацию в обратную
сторону не переносит.

Это не дефект реализации, а следствие выбранного направления подстановки.

## 6. Архитектурный вывод

Module 0 подставляет **callee в caller**. Juliet показывает, что для целого
класса функций нужно обратное: **контекст вызывающего в callee**.

Для `badSink` полезной подстановкой была бы не его собственная callee-цепочка,
а фрагмент вызывающего, где объявлен буфер:

```c
/* контекст вызывающего */
char * dataBadBuffer = (char *)ALLOCA((10)*sizeof(char));
data = dataBadBuffer;
/* собственное тело */
char source[10+1] = SRC_STRING;
memcpy(data, source, (strlen(source) + 1) * sizeof(char));
```

Call graph для этого уже построен — рёбра нужны в обратном направлении, а
`CallGraph.callers` уже заполняется. То есть механизм переиспользуется почти
целиком.

Осложнение: у функции может быть много вызывающих, и выбирать придётся так же
по релевантности, как сейчас выбираются call-site. Плюс растёт риск разбавления
признаков (см. H1.1 в [HYPOTHESES.md](HYPOTHESES.md)).

## 7. Что установлено и что нет

**Установлено:**

- Module 0 корректно разрешает и подставляет межфайловые вызовы на 1767 файлах,
  93.5 % юнитов получают контекст, усечения нет;
- на функциях-вызывающих подстановка даёт **+0.260 AUC** — эффект есть и он
  большой;
- на функциях-приёмниках эффекта нет, и причина структурная, а не случайная.

**Не установлено:**

- абсолютное качество: метка утекает через имя, детектор не переносится на
  синтетику. Числа вида «precision 0.21» смысла не имеют;
- переносится ли эффект caller-функций на реальный код: на libtiff инлайнинг
  суммарно снижал скор (см. [CASE_STUDY_LIBTIFF.md](CASE_STUDY_LIBTIFF.md)),
  но там 31 % усечений и другое распределение;
- что даст дообучение на инлайненных юнитах — единственный способ отделить
  «модель не видела таких входов» от «инлайнинг вредит» (H1.2).

## 8. Воспроизведение

```bash
curl -LO https://samate.nist.gov/SARD/downloads/test-suites/2017-10-01-juliet-test-suite-for-c-cplusplus-v1-3.zip
unzip -q 2017-10-01-juliet-test-suite-for-c-cplusplus-v1-3.zip -d juliet
mkdir juliet_x
find juliet/C/testcases -name "*_51a.c" -exec cp {} juliet_x/ \;
find juliet/C/testcases -name "*_51b.c" -exec cp {} juliet_x/ \;
cp juliet/C/testcasesupport/std_testcase.h juliet/C/testcasesupport/io.c juliet_x/
```

```bash
for d in 0 2; do
  python scan_cli.py --project juliet_x --inline-depth $d --dry-run --json \
    --model-path code/saved_models/baseline/checkpoint-best-acc/model.bin \
    --output juliet_d$d.json
done
```

Метка: `bad` в имени функции → 1, `good` → 0, остальные (`printLine`, `main`)
из выборки исключены.
